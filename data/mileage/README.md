# ⑦ 마일리지(부산) — 수집·갱신 절차

이 탭의 자료는 **항공사가 공개하는 보너스 좌석 현황**(대한항공, 하루 1회 갱신 · 앞으로 360일)을
옮긴 스냅샷입니다. 원천은 등급별 **있음/없음**만 알려 주고, 좌석 수량·수수료 금액·기재·편명은
알려 주지 않습니다. 그래서 이 자료에도 넣지 않습니다.

## 1. 파일

| 파일 | 내용 |
|---|---|
| `data/mileage/captures/<YYYY-MM-DD>.json` | 그날 원천 화면에서 옮겨 적은 수집본(정본) |
| `data/mileage/snapshots/<YYYY-MM-DD>.json` | 수집본을 편 날짜별 스냅샷 — 다음 날 diff 기준 |
| `data/app/tab8_mileage.json` | 앱이 지연 로딩하는 배포본(빌드 산출물) |

## 2. 수집본 형식

```json
{"collectedAt":"2026-11-22T08:40:00+09:00",
 "observed":"2026-11-22 01:30",
 "rows":[
  {"code":"NRT","dir":0,"month":"2026-12","cells":"1:1,2:1,3:7,..."},
  {"code":"KIX","dir":0,"month":"2027-04","note":"원천 조회 불가"}
 ]}
```

- `dir` 0 = 부산(PUS)→현지, 1 = 현지→부산(PUS)
- `cells` — `일:비트` 목록. 비트 `1`=일반석 보너스(E) · `2`=프레스티지 보너스(P) · `4`=프레스티지 승급(U) · `8`=일등석(F) · `0`=보너스 좌석 없음 · `16`=운항편 없음
- 원천이 `검색하신 여정은 조회가 불가합니다` 로 답한 달은 `note` 로 남기고 `cells` 를 비웁니다(값을 채우지 않음).

## 3. 빌드

```bash
python3 tools/collect_mileage.py --build      # 수집본 → 앱 자료 + 스냅샷 + 전일 diff
python3 tools/collect_mileage.py --status     # 지금 있는 수집본 요약
python3 tools/master_db.py verify             # ⑦ 검사 포함(비트·날짜 창·집계·원천에 없는 항목)
```

## 4. 원천 화면에서 읽는 법 (브라우저)

`https://www.koreanair.com/booking/book-and-manage/award-seat-availability`

1. 왕복/편도 → 출발지 `부산/김해 PUS` → 도착지 → 탑승월 → **조회**
2. 결과 화면의 `가는 날` / `오는 날` 탭에서 달을 넘기며 날짜 칸을 읽는다
   (날짜 칸: `td[id^="day_"]`, 등급은 칸 안 문구 `일반석 보너스` · `프레스티지석 보너스` · `프레스티지석 좌석승급` · `좌석 없음` · `운항편 없음`)
3. 달을 한 번에 한 달씩 넘기며(다음 달) 12개월을 읽고, 수집본에 `일:비트` 로 적는다.

> 이 저장소를 만드는 환경(shell)은 항공사 사이트에 직접 닿지 못합니다(Akamai 403 — 데이터센터 IP).
> 그래서 `--fetch` 는 값을 만들지 않고 거절 사실만 알리고 멈춥니다. 수집은 **브라우저로 보이는 화면을
> 옮겨 적는 방식**이 확실합니다.

## 5. 권장 갱신 시각

원천이 **한국 시간 01:30 기준**으로 하루 1회 갱신되므로, 그 뒤인 **매일 02:00~04:00 KST**에
수집하고 `--build` → `verify` → 커밋·푸시하면 그날 저녁까지 최신 상태가 됩니다.
