### 전송용 압축 표현

`tools/master_db.py` 의 `encode_part()` 가 쓴 두 표현을 앱의 `hcDecode()` 가 원래 구조로 되돌립니다.

```
{"$d":"2026-12-01","$v":[240000,236000,…]}   →   {"2026-12-01":240000,"2026-12-02":236000,…}
{"$t":["id","name",…],"$r":[["h02","파크 하얏트 부산",…],…]}
                                               →   [{"id":"h02","name":"파크 하얏트 부산",…},…]
```

`$t`/`$r` 에서 값이 `"$~"` 인 칸은 그 행에 key 가 없는 것으로 풀립니다. 앱은 받은 JSON을
한 번 풀어서 쓰므로 화면 동작은 예전 단일 파일 때와 같습니다.

### 지연 로딩 규칙

- **첫 화면**은 `index.html`(1.09 MB) + `tab1_vip.json`(0.45 MB)만 받습니다 — 약 **1.5 MB**.
- **탭을 처음 누를 때** 그 탭의 JSON 하나만 받아 그리고, 이미 받은 탭은 다시 받지 않습니다.
- **✈️+🏨 콤보**는 ①~④ 호텔과 ⑥ 항공이 함께 필요하므로 아직 받지 않은 JSON만
  `Promise.all(fetch …)` 로 **병렬**로 받은 뒤 계산합니다. 콤보에서 **⑦ 땡처리 소스**를 고르면
  그때 `tab6_ttang.json` 까지 함께 받습니다.
- 받는 동안 화면 가운데에 「데이터 불러오는 중…」 카드가 뜨고(어떤 파일을 받는지 표시),
  실패하면 이유와 `다시 시도` 버튼을 보여 줍니다.
- `index.html` 의 `const DB` 에는 `hotels: []`(빈 배열) · `sources` · `built` · `voucherExpiry` ·
  `extended` · `accor: null` · **`counts`** 만 들어 있습니다. `const FLIGHTS` / `const TTANG` 은 빈 골격입니다.
- **로컬에서 열 때 주의**: 브라우저는 `file://` 에서 `fetch` 를 막습니다. `python3 -m http.server 8000`
  으로 띄운 뒤 `http://localhost:8000/` 로 열거나 GitHub Pages 주소를 쓰세요.

## 화면 기능

### 공통

- **🔒 PIN 잠금** — 첫 화면에 PIN 게이트가 뜹니다. PIN은 `tools/set_pin.py` 가 만든 해시만 파일에 심고,
  입력한 PIN은 기기 브라우저에만 남으며 전송되지 않습니다. 상단 `🔒 잠금` 버튼으로 다시 잠급니다.
- **달력 · 상태 요약 막대** — 지금 보는 달의 `요금 공개` / `—`(미공개·미조회) 칸 수와 이상치 의심 칸 수를 셉니다.
  값이 없는 이유가 다르면 칸 글자도 다릅니다(`—` / `0건` / `미공개` / `미오픈` / `판매 중지` / `직항없음`).
- **이상치 표시** — 1박 **1,000만 원 이상**은 빗금·붉은 글씨·`⚠` 로 표시하고, 평균·분포·최고가 계산에서 뺍니다(값 자체는 지우지 않음).
- **연박(2박·3박)** — ①~⑤ 호텔 필터의 `전체(1박) / 2박 연속 / 3박 연속`. 연속으로 요금이 있는 체크인 구간만 남기고 달력·상세·순위를 N박 합계로 바꿉니다.

```bash
python3 tools/master_db.py verify    # data/master_db.json == data/app/*.json + index.html 집계값 인지 검사
```

`verify` 가 보는 것: `const DB` 집계값이 정본과 같은지, 탭별 호텔 수·id 순서·내용이 정본과 같은지,
항공·땡처리·마일리지 JSON이 정본과 같은지, 날짜 창·패턴·예약창·`noSale`/`nofare`/`unopened` 규칙,
가격이 양의 정수인지(0원·추정 금지), (노선·출발일·패턴) 중복이 없는지, 교차 탭 중복(`alsoIn` 없는 이름 중복),
출처 문구에 제3자 사이트 이름이 남아 있지 않은지, 그리고 그날 스냅샷과 에러가 후보.

> **주의** — `verify` 의 호텔 검사 대상은 **①~③ 1,040곳**이고, ④ 하얏트(327곳)만은 `EXPECT_HYATT`
> (곳수·칸수·값 있는 칸)로 따로 검사합니다. ⑤ IHG와 🌲·🎉·🅿️·🛫·⑧ 외항사는 각 `build_*` 도구가 만든
> 별도 JSON이라 `verify` 가 내용을 대조하지 않습니다. 그 탭을 고쳤으면
> GitHub Pages에서 그 탭을 직접 열어 확인하세요.

## 배포 (GitHub Pages)

저장소 `toresyo2311-max/hotel-calendar-app`(public)의 Settings → Pages 는
**Source: Deploy from a branch / Branch: `main` / Folder: `/ (root)`** 입니다. 빌드 단계가 없어
루트의 `index.html` 과 `data/app/*.json` 이 그대로 게시되고, push하면 보통 1~2분 안에 다시 게시됩니다.

```
변경 → python3 tools/master_db.py verify → git add · commit → git push origin main → Pages 자동 재게시
```

- `data/app/*.json` 을 빠뜨리고 push하면 첫 화면은 열리지만 탭을 누를 때 로딩이 실패합니다. push 전에 `verify` 로 확인하세요.
- **`index.html`·`manifest.json`·아이콘**처럼 앱 셸을 바꿨으면 `sw.js` 의 `VERSION` 을 올립니다(현재 `teambusan-v5-2026-11-23z114`).
  데이터 JSON만 바뀌면 서비스워커가 네트워크 우선이라 필수는 아니지만, 새벽 자동 갱신 작업은 캐시 정리를 위해 버전을 함께 올립니다.
- 무료 계정의 GitHub Pages는 공개 저장소에서만 쓸 수 있어, 무료 크레딧이 소진된 Netlify에서 옮기면서 저장소를 public으로 전환했습니다.
  `netlify.toml` 은 남아 있지만 지금 배포에는 쓰지 않습니다. HTTPS는 기본 도메인에 자동 적용됩니다.
